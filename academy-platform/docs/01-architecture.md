# المعمارية — منصة الأكاديمية التعليمية (Android فقط)

## 1. القرارات التقنية

| الطبقة | الاختيار | السبب |
|---|---|---|
| تطبيق الطالب | Kotlin + Jetpack Compose + Media3 (ExoPlayer) | وصول مباشر لـ FLAG_SECURE وAndroid Keystore وMedia3 لـ HLS/DRM، دعم RTL ممتاز |
| لوحة الإدارة | Next.js (React) + TypeScript | تعمل في المتصفح، دعم RTL، سهولة النشر |
| Backend | NestJS (TypeScript) + TypeORM/Prisma-بديل: SQL مباشر عبر migrations | هيكلة وحدات واضحة، Guards للصلاحيات، Throttler لتحديد المعدل |
| قاعدة البيانات | PostgreSQL 15+ | قيود وفهارس وtransactions للتزامن |
| تخزين الفيديو والملفات | S3-compatible خاص (Cloudflare R2 / Backblaze B2 / MinIO محليًا) | روابط موقعة مؤقتة، MinIO مجاني للتطوير |
| البث | HLS مشفر (AES-128) عبر مفاتيح يخدمها الـ API بعد التحقق | بديل واقعي عن DRM الكامل؛ يمكن الترقية لاحقًا إلى Widevine L3 |
| الإشعارات | Firebase Cloud Messaging | مجاني بحدود سخية |
| الجلسات | Access token قصير (15 د) + Refresh token دوّار مخزَّن مجزّأ في DB | إبطال فوري وربط بالجهاز |
| كلمات المرور | Argon2id | مقاوم لهجمات GPU |

> خدمات قد تكون مدفوعة: التخزين والـ egress للفيديو، بوابة الدفع (رسوم معاملات)، DRM تجاري، الاستضافة. بدائل مجانية للتطوير: MinIO، PostgreSQL محلي، FCM.

## 3. تدفقات أساسية (كلها تُتحقق على الخادم)

**الدخول وربط الجهاز:** التطبيق يرسل (هاتف/بريد، كلمة مرور، `device_fingerprint`، اسم الجهاز). عند أول دخول يُنشأ سجل في `devices`. عند محاولة الدخول من جهاز آخر والحساب مرتبط بجهاز نشط → رفض وتسجيل محاولة في `audit_logs`. الـ fingerprint مجرد معرّف مساعد؛ الاعتماد الفعلي على refresh token مرتبط بـ `device_id` + (لاحقًا) Play Integrity للتحقق من أصالة التطبيق.

**تشغيل الفيديو:** التطبيق يطلب `POST /lectures/:id/playback` ← الخادم يتحقق من (الجلسة، الجهاز، الاشتراك/المعاينة المجانية، موعد النشر) ← يُنشئ `watch_session` ويعيد رابط manifest موقّعًا قصير الأجل + رمز مفتاح تشفير مرتبط بالجلسة. العلامة المائية تُرسم داخل التطبيق (اسم + هاتف مقنّع) بمواضع عشوائية.

**تقدم المشاهدة:** التطبيق يرسل heartbeat كل ~15 ثانية بأحداث (play/pause/seek/rate). الخادم يحسب المدة الفعلية من الفارق الزمني بين heartbeats على ساعته مع سقف معقول (لا يقبل قفزات غير منطقية)، ولا يقبل نسبة مرسلة من التطبيق.

**الامتحانات:** `start` ينشئ attempt مع `started_at` و`expires_at` من الخادم؛ الإجابات تُحفظ تدريجيًا؛ `submit` أو انتهاء الوقت يصحح على الخادم فقط. استعادة الجلسة بإعادة قراءة attempt الجاري.

**الأكواد:** التفعيل داخل transaction مع `SELECT … FOR UPDATE` على الكود لمنع الاستخدام المزدوج؛ تُخزن الأكواد مجزّأة (HMAC) ولا تُعرض كاملة إلا عند الإنشاء.

**التنزيل دون إنترنت:** (مرحلة لاحقة) ملف مشفر بمفتاح لكل (مستخدم، جهاز، محاضرة) محفوظ بـ Android Keystore، مع `expires_at` ويتحقق التطبيق من الاشتراك عند الاتصال.

## 4. حدود الحماية (صريحة)

- FLAG_SECURE يمنع لقطات الشاشة والتسجيل الاعتيادي، لكنه لا يمنع تصوير الشاشة بكاميرا خارجية ولا الأجهزة المعدّلة (root).
- العلامة المائية تردع التسريب وتساعد في تتبعه ولا تمنعه.
- ربط الجهاز يقلل مشاركة الحسابات ولا يلغيها.
- بيانات المشاهدة مؤشر تقني وليست إثباتًا على انتباه الطالب.

## 5. الأدوار

`admin` (كل شيء) · `content_manager` (المحتوى والأكواد دون إعدادات النظام) · `teacher` (كورساته وطلابه فقط) · `student`. تُفرض عبر Guards على الخادم وتُحقق ملكية المدرس للكورس في كل استعلام.
